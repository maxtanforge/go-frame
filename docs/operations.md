# 业务服务运行约束

Frame 是由业务工程导入的 Go 基础库，不作为独立服务部署。镜像构建、Docker/Compose、
Kubernetes 清单、systemd 单元、发布流程与密钥管理由业务仓库或平台团队维护。
框架仓库中的 examples 用于验证组件接线；`templates/service` 提供业务工程起点，
复制后由消费方持有。框架不附带可直接上线的部署清单。

## 生命周期与健康检查

业务入口显式装配 `app`、`http/server`、`app/resource` 和 `health`。依赖先初始化并探活，
成功后 HTTP 才开始接收请求；启动失败回滚已创建的资源。

业务服务接到退出信号后，应先将 readiness 设为不可用，等待负载均衡摘流，再排空请求、
逆序释放依赖，最后关闭日志。`SHUTDOWN_DELAY` 和清理预留都计入 `SHUTDOWN_TIMEOUT`；
平台终止宽限期必须覆盖应用退出预算、日志收尾及平台自身的停止步骤。回调需要配合 context 取消。
`SHUTDOWN_TIMEOUT` 约束 App 的协作式关停阶段，不是整个进程的硬退出期限；
日志 Close 没有 context 参数，会等待归档维护完成。慢磁盘、阻塞 stdout 或压缩积压
仍可拖长退出时间，应在目标环境验证并为平台终止宽限期预留余量。
`OnShutdown` 只做快速状态切换。资源 `Stop` 与服务 `Shutdown` 应将 context 传给 I/O；
没有 context 的 `Close` 由适配器自身约束阻塞。HTTP 升级后的连接由业务持有，
需要在业务停机流程中主动关闭。

负载均衡探测每个实例的 `/readyz`，退出摘流后停止分配新请求。`/healthz` 不检查数据库，
避免后端故障触发所有副本重启。摘流等待应根据实际传播延迟设置，框架不保证零失败切换。

## 配置、日志与密钥

- 业务决定监听地址、端口和网络暴露方式；服务模板默认回环监听，对外监听需显式配置。
- 实例统一记录 `service`、`version`、`environment`、`instance_id`。显式实例 ID 必须在副本间唯一。
- 容器通常输出 stdout，由平台采集和轮转；虚拟机可使用文件或 journal。
  文件日志使用 `<LOG_DIR>/<INSTANCE_ID>/service.log`，一个路径只能由一个进程写入。
  日志根目录应由运维管理，不允许不可信用户修改目录内容或符号链接。
- 文件保留只管理当前实例路径。随机实例 ID 重启会产生新目录；稳定 ID 分配及退役目录清理由业务运维负责。
- 生产凭据由部署环境或受控文件注入。业务镜像的构建上下文、缓存和源码提交都必须排除私有文件；
  多阶段构建不能代替密钥隔离。
- Redis TLS/mTLS 使用 `REDIS_TLS_ENABLED` 及 `REDIS_TLS_CA_FILE`、`REDIS_TLS_CERT_FILE`、
  `REDIS_TLS_KEY_FILE` 等配置，路径指向服务运行环境中的文件；框架默认验证证书。

## 多副本与数据约束

- 会话、幂等记录及跨副本共享状态由业务显式放入共享后端，进程内状态不会自动同步。
- Snowflake 每个活动生成器必须独占 `ID_NODE`（0–1023），不能从 Pod UID/IP 或 INSTANCE_ID
  哈希推断。节点重用、进程重启和时钟范围由部署方管理，见 [ID 约束](../id/README.md)。
- 数据库和 Redis 的总连接预算按“同时持有连接池的实例数 × 每实例池上限”计算，
  包括滚动发布新副本、尚未释放资源的旧副本，以及运维余量，不能只按稳定副本数计算。
- 业务选择需要的 MySQL/PostgreSQL 驱动，显式应用 schema；框架不自动执行迁移或注册服务。

## 验收归属

库内测试验证组件契约；真实 MySQL/PG/Redis 测试及执行记录见 [集成验证](integration-testing.md)。
业务项目在目标环境验证启动失败回滚、后端故障恢复、退出摘流与排空、日志写入失败和滚动发布。
交叉编译或框架测试通过不等于业务部署已经验收。
