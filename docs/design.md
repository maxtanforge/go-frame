# 设计说明

go-frame 提供业务服务反复使用的运行机制。业务工程选择能力包，在入口装配依赖，并持有授权、事务范围、部署配置和后台任务策略。具体包职责、依赖方向和公共入口见[整体架构设计](architecture.md)。

## 关键取舍

| 决策 | 原因与代价 |
|---|---|
| 单 Go module，按能力拆包 | 统一版本和消费验证。包可以按需导入，各包随同一个模块版本发布。 |
| 构造函数显式接收依赖 | 装配点能看到驱动、资源和所有者。新增依赖需要修改接线并在消费工程验证。 |
| 核心与适配分层 | 生命周期、配置解码和 SQL 基础能力可独立使用。HTTP、驱动和观测 SDK 由相应适配包接入。 |
| 业务定义事务和授权边界 | 框架提供事务执行和 HTTP 认证机制，业务用例决定哪些操作需要原子性和授权。 |

## 启动与停机

1. 业务入口加载并验证配置，再创建日志运行时。配置预检可以独立执行。
2. `app` 按 Hook 依赖顺序启动资源并探活。组合 Hook 借用就绪资源，构造业务依赖和路由，再注册 HTTP 服务。
3. 停机先撤下 readiness，再排空服务并逆序关闭资源，最后由启动层关闭日志。启动失败也按已进入的阶段逆序回滚。

停机预算由回调协作执行。目标环境的宽限期及资源关闭约束见[运行指南](operations.md)，完整接线见[服务模板](../templates/service/README.md)。

## 请求与数据边界

HTTP 适配层绑定并验证请求 DTO，把输入转换为业务命令或查询。业务用例依赖自身定义的接口，持久化适配负责执行 SQL 或 Ent 操作。结果由 HTTP 层映射成响应 DTO 和公开错误。签名回调和流式传输可以使用原生 HTTP 处理入口。

接入示例和事务边界见[业务装配指南](business-integration.md)，公开能力的用法见[能力参考](reference.md)。验证这些边界时，使用[依赖测试和独立消费验收](verification.md)。
